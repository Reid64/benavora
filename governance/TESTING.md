## Six Laws Verification Plan

### Law 1 – Schema Integrity (Automated)
**Verification:** Jest/Vitest database tests connect to the Supabase test instance and assert:
- `organization_id` column exists on every multi-tenant table: `grants`, `research_runs`, `research_run_agents`, `search_profiles`, `alerts`, `consensus_validations`, `agents`
- RLS is enabled (`relrowsecurity=true`) on each of these tables
- At least one RLS policy exists per table
- A cross-tenant SELECT (JWT from Org B querying Org A data) returns zero rows

Runs on every pull request in CI.

### Law 2 – API Contract Integrity (Automated)
**Verification:** Vitest + supertest integration tests cover:
- Every route returns 401 without auth token
- Every mutating route returns 403/404 for cross-tenant resource access
- Viewer role JWT blocked from all admin/member-only routes
- All HTTP status codes match specification (409 concurrent, 400 validation, 404 not-found)

Runs on every pull request in CI.

### Law 3 – UI Integrity (Automated)
**Verification:**
- `page.on('console', ...)` catches hydration errors in all Playwright specs
- axe-playwright accessibility scan on all 13 page routes (zero critical/serious violations)
- Empty state and error state verified by intercepting APIs to return 200/[] and 500 respectively
- `next build` TypeScript strict mode must succeed (zero errors) in CI
- Static analysis grep confirms all Recharts components use `dynamic(..., { ssr: false })`

### Law 4 – Data Integrity (Automated)
**Verification:**
- Zod schema unit tests for every API route request body
- Database constraint tests: invalid enum INSERT, NULL organization_id INSERT, orphaned FK INSERT
- Deduplication logic unit test: URL normalization, Levenshtein fuzzy match, metadata merge
- Cron job test: research_runs rows >10 min old with status=running are marked failed
- Default value tests: existing grants show `source_type='other'` and `eligibility_flag='unscored'` after migration

### Law 5 – Wiring Integrity (Automated)
**Verification:**
- Playwright network intercept assertions: every form submit calls correct API route with correct payload
- Supabase Realtime test: direct DB write to `research_run_agents` triggers UI card update within 5 seconds
- Agent integration tests with mocked AI providers: assert correct prompts, correct provider calls (Claude for primary, GPT-4o for consensus), correct DB writes after each agent
- Optimistic update rollback test: delayed + failed PATCH causes badge revert

### Law 6 – Human Verification (Manual, Required for Production Deploy)
**Verification:** QA Engineer + Product Owner sign-off required:
1. Full Playwright suite pass on Vercel preview
2. Manual walkthrough of all 7 PRD features against interaction maps
3. Badge color verification against exact Tailwind classes from PRD
4. Cross-browser Recharts rendering check (Chrome, Firefox, Safari)
5. /outcomes → /analytics redirect confirmed
6. Manual tenant isolation check with two test organizations
7. Empty/error/loading states confirmed on all dashboard panels
8. Sign-offs recorded in deployment checklist before production deploy

- Returns 401 when no auth token provided
- Returns empty array (not 404) when organization has no grants
- Filters by source_type=federal_government query param, returns only matching grants
- Filters by eligibility_flag=high_match query param, returns only matching grants
- Filters by multiple source_types (comma-separated), returns union of matching grants
- Does NOT return grants from other organizations even if grant IDs are guessed
- Returns 400 with validation error when source_type param is not a valid enum value
- Respects pagination via page and limit query params, returns correct slice
- Returns grants with source_type, match_percentage, eligibility_flag, eligibility_notes fields populated

### `GET /api/grants/[id]`
- Returns 200 with full grant object including source_type, match_percentage, eligibility_flag, eligibility_notes for own organization grant
- Returns 404 when grant belongs to different organization (tenant isolation via RLS)
- Returns 401 when no auth token provided
- Returns 404 when grant ID does not exist

### `PATCH /api/grants/[id]`
- Returns 200 and updates source_type when valid enum value provided and user owns grant
- Returns 400 when source_type value is not a valid enum member
- Returns 403 or 404 when patching grant belonging to different organization
- Returns 401 when no auth token provided
- Returns 403 when authenticated user has viewer role
- Returns 404 when grant ID does not exist
- Ignores unknown fields in request body (does not throw)
- Returns updated grant object in response body

### `POST /api/grants/[id]/rescore`
- Returns 200 and triggers eligibility re-scoring for own organization grant
- Returns updated match_percentage, eligibility_flag, eligibility_notes in response
- Returns 404 when grant belongs to different organization
- Returns 401 when no auth token provided
- Returns 403 when user has viewer role
- Returns 400 when no search profile is configured for organization (includes descriptive error message)
- Returns 404 when grant ID does not exist
- Sets eligibility_scored_at timestamp on successful rescore

### `POST /api/research/run`
- Returns 201 and creates research_runs row with status=running when no run is in progress
- Returns 409 when a research_runs row with status=running already exists for organization
- Returns 401 when no auth token provided
- Returns 403 when user has viewer role
- Accepts optional search_profile_id and associates it with the research_runs row
- Creates research_run_agents rows for each active agent in the organization
- Returns 400 when organization has no active agents configured

### `GET /api/research/runs`
- Returns 200 with array of research_runs scoped to authenticated organization
- Returns 401 when no auth token provided
- Returns runs with deduplication_stats JSONB populated after completion
- Returns runs in descending started_at order by default
- Does not return runs from other organizations

### `GET /api/research/runs/[id]`
- Returns 200 with full run object including research_run_agents array
- Returns 404 when run belongs to different organization
- Returns 401 when no auth token provided
- Returns 404 when run ID does not exist

### `GET /api/search-profiles`
- Returns 200 with search profile for authenticated organization
- Returns 404 when no profile exists for organization
- Returns 401 when no auth token provided
- Returns profile with all fields: funding_types, source_type_filters, focus_area_weights, amount_min, amount_max, geographic_scope, eligibility_filters, negative_filters

### `POST /api/search-profiles`
- Returns 200 and creates new search_profiles row when none exists for organization
- Returns 200 and updates existing search_profiles row (upsert by organization_id)
- Returns 401 when no auth token provided
- Returns 403 when user has viewer role
- Returns 400 when funding_types array is empty
- Returns 400 when amount_min exceeds amount_max
- Returns 400 when geographic_scope type is state-specific but states array is empty
- Treats amount_max of 0 as NULL (no upper limit) and stores NULL in database
- Sets updated_at timestamp on every upsert
- Strips unknown fields from request body before saving

### `GET /api/analytics/summary`
- Returns 200 with summary metrics for authenticated organization
- Returns 401 when no auth token provided
- Accepts from and to query params (ISO date strings) and filters data to date range
- Returns zero-value metrics (not errors) when organization has no grants
- Does not include data from other organizations

### `GET /api/analytics/funnel`
- Returns 200 with counts per grant status stage scoped to organization
- Returns 401 when no auth token provided
- Returns all funnel stages with count 0 when no grants exist (not missing stages)
- Accepts date range params and filters accordingly

### `GET /api/analytics/financials`
- Returns 200 with monthly aggregated amount_requested and amount_awarded
- Returns 401 when no auth token provided
- Skips NULL amount rows without throwing errors
- Returns empty array (not error) when no financial data exists
- Accepts from and to query params and returns correct monthly buckets

### `GET /api/analytics/by-source`
- Returns 200 with source_type breakdown including count and total_amount per type
- Returns 401 when no auth token provided
- Returns only source types present in organization's grants
- Correctly aggregates grants with NULL source_type under 'other' category

### `GET /api/analytics/deadlines`
- Returns 200 with date-count pairs for grants with deadlines in next 90 days
- Returns 401 when no auth token provided
- Returns empty array (not error) when no upcoming deadlines exist
- Does not include deadlines from other organizations
- Only includes dates in the future (not past deadlines)

### `GET /api/analytics/agent-activity`
- Returns 200 with daily research run and grant discovery stats
- Returns 401 when no auth token provided
- Returns empty array (not error) when no research runs exist

### `GET /api/alerts`
- Returns 200 with alerts array scoped to authenticated organization
- Returns 401 when no auth token provided
- Returns unread alerts before read alerts (sorted by read status then created_at desc)
- Does not return alerts from other organizations
- Returns correct unread_count in response metadata

### `POST /api/alerts/[id]/read`
- Returns 200 and marks alert as read for own organization alert
- Returns 404 when alert belongs to different organization
- Returns 401 when no auth token provided
- Returns 404 when alert ID does not exist
- Is idempotent: marking already-read alert returns 200 without error

### `POST /api/alerts/read-all`
- Returns 200 and marks all unread alerts as read for authenticated organization
- Returns 401 when no auth token provided
- Returns 200 with affected_count=0 when all alerts already read
- Only marks alerts read for the authenticated organization, not others

### `POST /api/consensus/validate`
- Returns 201 and triggers consensus validation for own organization grant
- Returns 401 when no auth token provided
- Returns 403 when user has viewer role
- Returns 404 when grant_id belongs to different organization
- Returns response with claude_score, gpt4o_score, consensus_score, agreement_status, combined_rationale fields
- Returns 400 when grant_id is missing from request body
- Stores validation result in consensus_validations table with correct organization_id

### `GET /api/consensus/[grant_id]`
- Returns 200 with most recent consensus validation result for own organization grant
- Returns 404 when no validation exists for the grant
- Returns 404 when grant belongs to different organization
- Returns 401 when no auth token provided
- Returns validation with claude_score, gpt4o_score, consensus_score, agreement_status, combined_rationale, validated_at
