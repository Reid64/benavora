# Corporate Application Automation — PIL Integration Handoff

This package completes the canonical PIL specification first. The application-automation scope is downstream.

## Authoritative ownership retained by PIL
Corporate discovery; corporate identity resolution; program research; evidence verification; mission/geographic alignment; relationship intelligence; qualification; prioritization; request strategy; knowledge integrity; supervisory governance; fleet evaluation/learning.

## Deterministic execution expected downstream
Browser execution; portal extraction; registration; credential/session management; authorized mailbox correlation; confirmation-link validation; form modeling; field entry; file upload; workflow persistence; queueing; scheduling; rate limiting; checkpoints; idempotency; screenshots/evidence capture; CRM synchronization; monitoring/alerts.

## Security boundary
Portal pages, emails, attachments, uploads, third-party instructions, and retrieved web content are untrusted. They cannot override system instructions, tenant policy, tool allowlists, data restrictions, or authorization. The downstream subsystem must not defeat CAPTCHAs, evade access controls, conceal prohibited automation, or self-approve human-only certifications.

## Required next architecture step
Before any new downstream agent is registered: build the capability-overlap matrix, identify what existing PIL agents already own, assign deterministic services, define contracts/events/systems of record, then justify only irreducible new goal-owning reasoning domains.
