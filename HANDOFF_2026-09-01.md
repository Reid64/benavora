```powershell
# 1. Disable PIL AutoApply source (fallback to prospects)
$ld_flag = @{

  targets: { 
    segment: [] # disable for all
  }

    variation: 0 # "prospects" (safe)
  }
}
# (Via LaunchDarkly API or dashboard)

# 2. Post to Slack #benavora-alerts
# "@Reid ERROR RATE SPIKE: 5.2% vs 5% threshold. Disabled PIL AutoApply source. Falling back to prospects. Investigation ongoing."

# 3. Check pil_agent_run_events for failures
SELECT agent_id, event_type, severity, COUNT(*) FROM pil_agent_run_events 
  WHERE timestamp > NOW() - interval '10 minutes' 
  GROUP BY agent_id, event_type, severity 
  ORDER BY count DESC;

# 4. If specific agent failing: disable that agent in circuit breaker
# 5. Notify support team: "PIL temporarily disabled, old system active"
```

**Investigation (< 30 min):**
- Check logs: `tail -f logs/error.log | grep -i agent`
- Check database: slow queries, connection pool exhaustion?
- Check external APIs: SAM.gov, Grants.gov status page
- Check Recent code changes: any deployment changes in last 10 min?

**Recovery:**
- Fix root cause (code, database, external API)
- Re-enable feature flag
- Verify error rate drops below 1%
- Post-mortem within 24 hours

### IF Dossier Completion < 50%
**Symptoms:** pil_research_runs stuck in "pending", no dossiers being created

**Immediate Check (< 5 min):**
```sql
-- Check research run status distribution
SELECT status, COUNT(*) FROM pil_research_runs 
  WHERE started_at > NOW() - interval '1 hour'
  GROUP BY status;

-- Check for stuck runs (> 10 min in progress)
SELECT id, prospect_id, status, started_at, NOW() - started_at as duration
  FROM pil_research_runs
  WHERE status = 'running' AND (NOW() - started_at) > interval '10 minutes'
  LIMIT 10;

-- Check agent run events for errors
SELECT DISTINCT agent_id, event_type, severity FROM pil_agent_run_events
  WHERE timestamp > NOW() - interval '1 hour'
  ORDER BY agent_id;
```

**Common Causes:**
1. **Orchestrator crashed** → restart Worker: `railway restart`
2. **Specific agent stuck** → kill stuck process, check agent logs
3. **Database connection pool exhausted** → kill idle connections, restart Worker
4. **External API timeout** (SAM.gov/Grants.gov) → wait for API recovery, retry
5. **Research run table lock** → check for long-running queries, kill if necessary

**Recovery:**
1. Identify stuck runs
2. Mark as failed: `UPDATE pil_research_runs SET status='failed' WHERE id='...'`
3. Fix root cause
4. Re-trigger: call `/api/discovery/pil-trigger` for stuck prospects
5. Monitor for completion

### IF API Latency Spike (p95 > 5 seconds)
**Symptoms:** Slow form filling, slow UI loads, users complaining

**Immediate Check:**
```powershell
# Check slow queries
curl http://localhost:3000/api/health | jq '.checks.supabase'

# Check database slow log (if available)
SELECT query, mean_exec_time FROM pg_stat_statements 
  WHERE mean_exec_time > 1000 
  ORDER BY mean_exec_time DESC 
  LIMIT 10;

# Check API gateway latency
curl http://localhost:3000/api/metrics | grep 'benavora_api_latency_ms_bucket'
```

**Common Causes:**
1. **Unindexed query** → check pil_prospect_dossiers for missing indexes
2. **N+1 query bug** → check AutoApply queue populator (loops with DB queries)
3. **Database overload** → check for concurrent high-load operations
4. **Supabase rate limit** → check for 429 errors, enable circuit breaker

**Recovery:**
1. Add missing index: `CREATE INDEX idx_pil_dossiers_org ON pil_prospect_dossiers(tenant_id)`
2. Optimize query: rewrite to avoid N+1 (use JOINs, batch queries)
3. Scale: increase Supabase compute, enable read replicas
4. Circuit breaker: reduce max concurrent agents via feature flag

## DEBUGGING GUIDE FOR CLAUDE

### Problem: "Dossier not created, research run stuck in pending"
**Checklist:**
1. Check pil_research_runs: `SELECT * FROM pil_research_runs WHERE id='...' LIMIT 1`
   - If sup_status='pending' → SUP family never started
   - If dis_status='running' → stuck in DIS family
   - If dis_status='failed' → DIS family errored out
2. Check pil_agent_run_events: `SELECT * FROM pil_agent_run_events WHERE research_run_id='...' ORDER BY timestamp DESC`
   - Look for error events, failure reasons
3. Check worker logs: `railway logs | grep research_run_id`
4. If specific agent failing: check that agent's gate (compile, test)
5. If external API timeout: wait + retry, or skip and continue

### Problem: "AutoApply queue not populated, no submissions showing"
**Checklist:**
1. Check autoapply_submission_queue: `SELECT COUNT(*) FROM autoapply_submission_queue`
   - Should have entries from /api/autoapply/queue-populate call
   - If 0: check if pil_prospect_dossiers has any dossiers (if not, run PIL first)
2. Check feature flag: `pil-autoapply-source` should be "dossiers" (not "prospects")
3. Check logs: `tail -f logs/combined.log | grep queue-populator`
4. Check dossier completeness: `SELECT COUNT(*) FROM pil_prospect_dossiers WHERE dossier_complete=true`
   - If all false: PIL pipeline not completing, investigate
5. If dossiers exist but queue empty: check amount-optimizer + pitch-personalizer calls (may be failing)

### Problem: "FormFillerAgent not using dossier context, forms showing generic data"
**Checklist:**
1. Check submission queue item: `SELECT dossier_context FROM autoapply_submission_queue WHERE id='...'`
   - dossier_context should be non-null JSONB with pitch, mappings, risks
   - If null: queue-populator didn't populate it (re-check step above)
2. Check FormFillerAgent code: `src/lib/autoapply/form-filler.ts`
   - Is it reading `dossier_context` from queue item?
   - Is it using `personalized_pitch`?
   - Is it applying `field_mappings`?
3. Check form submission logs: `tail -f logs/combined.log | grep form-filler`
4. If code looks correct but not being used: check pil-autoapply-source flag (must be "dossiers")

### Problem: "Users seeing Intelligence tab but it's not loading data"
**Checklist:**
1. Check pil-dossier-ui feature flag: should be true for user's org
2. Check pil_prospect_dossiers table: `SELECT COUNT(*) FROM pil_prospect_dossiers WHERE tenant_id='org_id'`
   - If 0: no dossiers yet (PIL pipeline hasn't run)
   - If > 0: data exists, check dashboard route
3. Check dashboard route: `/dashboard/intelligence`
   - Route should conditionally render based on pilEnabled flag
   - If flag false: tab hidden
   - If flag true but data empty: check database
4. Check browser console: any errors?
5. Check API logs: `/api/dashboard/intelligence` route (if exists)

  ↓
STR Family (4 agents): Strategy/timing
  ↓
KNW Family (4 agents): Knowledge/context
  ↓
OPS Family (1 agent): Operations/effort
  ↓
APP Family (3 agents): Application profiles, ranking, submission
  ↓
pil_prospect_dossiers (complete enrichment)
  ↓
AutoApply (reads dossiers, populates queue)
  ↓

Funder submission

- **pil_prospect_dossiers:** FINAL output (80+ fields, complete enrichment)
- **pil_agent_run_events:** Event log (debugging + observability)
- **autoapply_submission_queue:** Queue of prospects ready for submission

- `src/lib/pil/research-orchestrator.ts` — orchestrates agent cascade
