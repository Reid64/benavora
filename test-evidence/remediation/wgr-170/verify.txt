2. ROOT CAUSE
   supabase/migrations/038_intelligence_tables.sql's CREATE TABLE for
   success_probability_scores declares `application_id uuid ... UNIQUE`
   inline. But per migration 145's own header comment
   (145_giving_history_and_probability_scores_column_drift.sql), this table
   already existed live, created out-of-band, before migration 038 ever ran --
   so 038's `CREATE TABLE IF NOT EXISTS` no-op'd against the live table and
   its inline UNIQUE constraint was never actually applied live. Migration 145
   already closed the same drift for the data_quality/created_at/updated_at
   columns; this closes it for the unique constraint, which is why every
   success-probability write 42P10's in production.

3. FIX
   Added supabase/migrations/149_success_probability_scores_unique_constraint.sql:
     DO $$ BEGIN
       ALTER TABLE success_probability_scores
         ADD CONSTRAINT success_probability_scores_application_id_key
         UNIQUE (application_id);
     EXCEPTION WHEN duplicate_object THEN NULL;
     END $$;
   Idempotent (safe to re-run; no-ops if the constraint already exists).
