NOTE ON RETRIEVAL FIX APPLIED DURING VERIFICATION
---------------------------------------------------
searchKnowledge() in src/lib/knowledge/db.ts originally called the RPC through
supabase-js's .schema("knowledge") helper. That schema is not in the Supabase
project's PostgREST exposed-schemas list (by design - service-role-only,
SECURITY DEFINER functions), so every call 404'd with PGRST106 regardless of
key. Fixed by querying knowledge.search()/knowledge.rate_count() over the
existing direct Postgres connection (same DATABASE_URL already used by
scripts/knowledge/ingest.ts), matching how the schema was actually designed to
be reached.

Second issue found while testing: idx_knowledge_chunks_embedding is an ivfflat
index built with lists=100, oversized for the current ~800-chunk corpus
(~8 rows/list). The pgvector default probes=1 only scans one list, so
searchKnowledge() returned just 1-3 hits per query instead of 5. Fixed by
setting ivfflat.probes=20 for the duration of the search() call in
searchKnowledge() (session-level SET on a dedicated pool client, not a global
DB config change). Both fixes are contained to src/lib/knowledge/db.ts.
