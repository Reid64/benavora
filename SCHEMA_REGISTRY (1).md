## NOTES ON SPECIFIC TABLES

### tenant_signals (Table 51)
This is the heart of the Recommendations Engine. Every alert, advisory, and Next Best Action surfaces through this table. The Command Center polls this table every 30 seconds. RLS ensures operators only see signals for their own clients.

### llm_calls (Table 47)
Replaces the aggregate `clients.llm_cost_today` field with granular per-call tracking. The aggregate field still exists in clients table for fast cost-cap checks, but every actual LLM call is logged here for cost attribution, debugging, and audit.

### page_decisions (Table 38)
Every decision A-05 makes (approved, rejected, flagged, requires_review) is logged here with full reasoning. This is the audit trail when an operator asks "why was this page flagged?"

### operator_actions (Table 39)
Every manual override an operator performs (overriding a quality gate, force-publishing a flagged page, manually pausing a client) is logged here with required justification.

### client_risk_profiles (Table 44)
Adjusts drip publishing velocity based on per-client risk factors. New domain = lower multiplier (slower publishing). Established domain with no penalties = higher multiplier (faster publishing). Multiplier ranges 0.10 to 2.00.

### demo_requests (Table 52)
Marketing landing page form submissions. Stores lead data + Google Calendar event ID created via API. Status tracks lead through funnel (submitted → scheduled → completed).

## RLS VERIFICATION

Every table has Row-Level Security enabled. Cross-tenant access is impossible by design. RLS policies enforce:

- **Operator tables** (clients, pages, etc.): operator sees only own clients
- **Client-derived tables** (services, cities, conversions, etc.): joined through clients table
- **Reference tables** (pricing_tiers, sub_processors, platform_config): authenticated read for all
- **Audit tables** (cron_run_log, security_events, audit_log): authenticated read for all
- **Per-operator tables** (operator_actions): operator sees own actions only
- **Per-user tables** (session_logs): user sees own sessions only

CRON-02 runs cross-tenant leak detection daily. Any leak = P0 alarm.
